# CLAUDE.md

Инструкции для Claude Code при работе с монорепозиторием **Tracker: AI Budget App**.

## О проекте

Учебный пет-проект: приложение для учёта личного бюджета с killer-фичей —
голосовой ввод трат (транскрибация речи → LLM парсит сумму/категорию/описание →
запись в БД). Цель пользователя — **разобраться, как устроен фулстек**;
промышленная готовность не приоритет.

Пользователь — фронтенд-разработчик, это его первый фулстек-проект. Бэкенд,
docker, nginx, TLS — новая для него территория: объясняй подробнее, чем фронт,
и проводи аналогии с фронтом, где уместно (DI ~ React Context, DTO ~ интерфейсы
пропсов). Новичком в программировании его не считать — фронт он знает хорошо.

Между сессиями бывают большие паузы. Возвращается — коротко напомни, на каком
этапе остановились (по корневому `README.md`).

Три каталога были тремя репозиториями; **слиты в монорепо 7 сентября 2026**
через `git subtree`, история обоих проектов сохранена. Старые репозитории
`Ko1iya/budget` и `Ko1iya/budget-web` заархивированы.

У `budget-api/` и `budget-web/` есть **собственные `CLAUDE.md`** с деталями —
читай их при работе внутри соответствующего каталога.

## Роадмап

Единый план этапов 1–6 (бэк + фронт + релиз) — в **корневом `README.md`**.
Это единственный источник правды по прогрессу; статус этапов отмечать там.
В README подпроектов этапы **не дублировать** — там только специфика.

## SPEC.md — живая спека

В корне `budget-api/` и `budget-web/` лежат `SPEC.md` — спецификации структуры
соответствующего проекта. Обновляй **в том же ответе**, что и изменение кода,
если создал/удалил/переместил файл в `src/`, изменил публичный API файла,
`prisma/schema.prisma` или `docker-compose.yml`. Подробные правила формата — в
`CLAUDE.md` каждого подпроекта.

**Why:** пользователь забывает контекст между паузами, SPEC.md — его способ
быстро восстановиться. Changelog в спеке не ведём — история в git.

## Стиль кода и комментариев

- **`budget-web` — комментарии короткие**: одна строка назначения, при
  необходимости краткий inline. Многострочные блоки не нужны — они перегружают
  код и дублируют SPEC.md.
- **`budget-api` и `tracker-deploy` — комментарии подробные**: это новая для
  пользователя территория, и объяснение «почему так» прямо в файле полезно
  (см. `docker-compose.prod.yml`, `Dockerfile`, `init-letsencrypt.sh`).
- Предпочитать **прозрачность и обучающую ценность** над
  production-best-practices, если они конфликтуют: явный код лучше хитрой
  абстракции. Не тащить сложные инструменты (Kafka, k8s, микросервисы) — для
  учебной цели это шум. Но и не упрощать до игрушечного: валидация, auth,
  миграции, error handling — всё это в плане есть и делается по-настоящему.
- Коммиты — на русском, в первом лице, коротко: «Реализовал удаление категории».

## Деплой

Стенд: **Timeweb Cloud VPS (EU-локация)** + Docker Compose + edge-nginx +
DuckDNS + Let's Encrypt. Инструкция на два этапа — в `tracker-deploy/README.md`.

Ключевые ограничения (не нарушать при правках инфраструктуры):
- **EU-локация обязательна** — бэк ходит на OpenRouter, из РФ это геоблок;
- **не брать VPS на 1 ГБ RAM** — сборка образов на сервере падает с OOM;
- **нужен валидный HTTPS**, не self-signed — иначе не работает `MediaRecorder`
  (голосовой ввод);
- `prisma generate` требует `DATABASE_URL` (из-за `prisma.config.ts` с `env()`) —
  на build-шаге Dockerfile подаётся фиктивный URL;
- `nest build` кладёт точку входа в `dist/src/main.js`, а не `dist/main.js` —
  поэтому entrypoint запускает `node dist/src/main`, а `start:prod` из
  `package.json` для прода неверен.
