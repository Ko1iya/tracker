# CLAUDE.md

Инструкции для Claude Code при работе с монорепозиторием **Tracker: AI Budget
App**. Это единственный `CLAUDE.md` в репозитории — подпроектных нет, все
правила здесь.

## О проекте

Учебный пет-проект: приложение для учёта личного бюджета с killer-фичей —
голосовой ввод трат (транскрибация речи → LLM парсит сумму/категорию/описание →
запись в БД). Цель пользователя — **разобраться, как устроен фулстек**;
промышленная готовность не приоритет.

Пользователь — фронтенд-разработчик, это его первый фулстек-проект. Бэкенд,
docker, nginx, TLS — новая для него территория: объясняй подробнее, чем фронт, и
проводи аналогии с фронтом, где уместно (DI ~ React Context, DTO ~ интерфейсы
пропсов). Новичком в программировании его не считать — фронт он знает хорошо.
Фронтовые концепции (React, Vite, хуки) разжёвывать не нужно, а вот стык с
бэкендом (CORS, JWT в заголовках, формат ответов API) — стоит пояснять.

Между сессиями бывают большие паузы, счёт идёт на месяцы. Возвращается — коротко
напомни, на каком этапе остановились (по корневому `README.md`).

## Структура и стек

```
tracker/
├── budget-api/      Бэкенд, NestJS. Свой SPEC.md.
├── budget-web/      Фронтенд, React 19 + Vite. Свой SPEC.md.
└── tracker-deploy/  Инфраструктура прода: docker-compose.prod.yml, nginx, certbot.
```

**`budget-api`** — NestJS + Prisma + PostgreSQL (в Docker), JWT-авторизация,
транскрибация речи через **Nexara**, LLM-парсинг через **OpenRouter**.

**`budget-web`** — React 19 + Vite + TypeScript, Tailwind CSS + shadcn/ui, React
Router, TanStack Query + axios (REST к `budget-api`), react-hook-form + zod для
форм, голосовой ввод на `MediaRecorder`. Дев-сервер `http://localhost:5173` уже
прописан в CORS бэка.

Впереди у обоих — Capacitor для мобилки.

`budget-api` и `budget-web` были отдельными репозиториями; **слиты в монорепо 7
сентября 2026** через `git subtree`, история обоих сохранена. Старые репозитории
`Ko1iya/budget` и `Ko1iya/budget-web` заархивированы. `tracker-deploy` создан
сразу здесь.

## Документация: что где живёт

Всё, что описывает **прогресс и состояние**, живёт в репозитории под git, а не в
памяти Claude — память пользователю невидима, следить по ней за прогрессом он не
может.

- **Корневой `README.md`** — единый роадмап этапов 1–6 (бэк + фронт + релиз) и
  статусы. Единственный источник правды по прогрессу.
- **`README.md` подпроектов** — только их специфика: как запустить, чем
  отличается. Этапы туда **не дублировать**, там указатель на корень. (Раньше
  роадмап был скопирован в оба и разошёлся — отсюда правило.)
- **Отдельные `.md` рядом с кодом** — детальное состояние подсистемы, например
  `tracker-deploy/README.md`: состояние прод-стенда, грабли, план CI/CD.
- **`SPEC.md`** в корне каждого подпроекта — структура кода, правила ниже.

Завершил или сдвинул этап — правь корневой `README.md` **в том же ответе**
(чекбоксы, дата «Последнее обновление»); это легко упустить. Правки README и
статусных `.md`.

## SPEC.md — живая спека

В корне `budget-api/` и `budget-web/` лежат `SPEC.md` — спецификации структуры
соответствующего проекта. Главный артефакт, который должен оставаться синхронным
с кодом.

**Why:** пользователь забывает контекст между паузами, SPEC.md — его способ
быстро восстановиться.

### Когда обновлять

Обновляй `SPEC.md` нужного подпроекта **в том же ответе**, что и изменение кода,
если ты:

- создал, удалил, переименовал или переместил файл в `src/`;
- изменил публичный API файла — экспорты, методы класса, поля DTO (бэк);
  экспортируемый компонент, его props, хуки, типы (фронт);
- **`budget-api`:** изменил `prisma/schema.prisma` (модель, поле, связь) или
  `docker-compose.yml`;
- **`budget-web`:** добавил, удалил или переименовал страницу/маршрут (React
  Router), либо изменил `index.html` / `vite.config.ts` так, что это влияет на
  структуру приложения.

Чисто внутренняя правка (рефакторинг приватной функции, разметки или стилей без
изменения смысла файла и его props) — `SPEC.md` можно не трогать.

Напоминание об этом шлёт hook в корневом `.claude/settings.json` (PostToolUse на
Edit/Write/MultiEdit) — он работает для обоих подпроектов, подпроектных
`.claude/` нет, все настройки Claude на уровне монорепо.

### Что должно быть в SPEC.md

**Только две секции верхнего уровня.**

1. **`## Project Structure`** — ASCII-дерево репозитория + краткие описания
   каждого файла (2–4 строки: назначение + ключевые экспорты/методы/props). Для
   `prisma/schema.prisma` — подсекция со списком моделей и их полей. Описывать
   только:
   - `budget-api`: `src/**`, `prisma/schema.prisma`, `docker-compose.yml`;
   - `budget-web`: `src/**`, `index.html`, `vite.config.ts`.

   **НЕ описывать** `node_modules/`, `dist/`, `test/`, `public/`, конфиги
   (`tsconfig*.json`, `eslint.config.*`, `nest-cli.json`, `prisma.config.ts`),
   `package*.json`, `.env*`, `.gitignore`.

2. Таблица маршрутов:
   - `budget-api` — **`## API Routes`**: Method, Route, Описание, Файл, Статус;
   - `budget-web` — **`## Routes`**: Path, Страница/компонент, Описание, Файл,
     Статус.

**НЕ добавлять** разделы Overview, Tech Stack, Changelog, Dependencies, How to
Run и т.п. — пользователь явно отказался от них.

### Стиль описаний

- **Язык:** русский для описаний, английский для технических терминов и имён
  сущностей. Примеры:
  `TransactionsService — слой бизнес-логики для CRUD транзакций`,
  `App — корневой компонент, монтирует роутер`.
- **Длина:** 2–4 строки на файл. Назначение + ключевые экспорты/методы/props.
- **Зависимости между файлами:** упоминай **только внешние интеграции** (Prisma,
  OpenRouter, Nexara, браузерные API вроде `MediaRecorder`). Внутренние импорты
  не дублируй — это видно в коде.
- **Удаления:** при удалении/переименовании файла убирай его из спеки без следа.
  Changelog не ведём — история в git.

### Ещё два правила

- **Не уверен в назначении файла** — не выдумывай, задай короткий вопрос: «Не
  понял назначение `X.ts` — опишешь одной строкой?»
- **При первом запросе на изменение `SPEC.md` в сессии** прочитай его целиком,
  прежде чем редактировать — чтобы не сломать описания соседних файлов.

## Стиль кода и комментариев

- **`budget-web` — комментарии короткие**: одна строка назначения, при
  необходимости краткий inline. Многострочные блоки не нужны — они перегружают
  код и дублируют SPEC.md. Развёрнутые объяснения — в ответе пользователю.
- **`budget-api` и `tracker-deploy` — комментарии подробные**: это новая для
  пользователя территория, и объяснение «почему так» прямо в файле полезно (см.
  `docker-compose.prod.yml`, `Dockerfile`, `init-letsencrypt.sh`).
- Предпочитать **прозрачность и обучающую ценность** над
  production-best-practices, если они конфликтуют: явный код лучше хитрой
  абстракции. Не тащить сложные инструменты (Kafka, k8s, микросервисы) — для
  учебной цели это шум. Но и не упрощать до игрушечного: валидация, auth,
  миграции, error handling — всё это в плане есть и делается по-настоящему.
- Коммиты — на русском, в первом лице, коротко: «Реализовал удаление категории».

## Деплой

Стенд: **FirstVDS, Амстердам** (2 vCPU / 4 ГБ / NVMe) + Docker Compose +
edge-nginx + DuckDNS + Let's Encrypt. Инструкция на два этапа и текущее
состояние стенда — в `tracker-deploy/README.md`.

Топология: edge-nginx терминирует HTTPS и проксирует `/` → web (статика) и
`/api/` → api (NestJS); рядом db (`postgres:16`) и certbot. Прод-секреты — в
`.env.prod` на сервере, в git и CI не попадают.

**Почему свой VPS, а не PaaS:** пользователь хочет пощупать сервер, docker и
nginx руками и при этом получить «релиз в одну кнопку» (CI/CD — отдельный этап).

Ключевые ограничения (не нарушать при правках инфраструктуры):

- **нужен валидный HTTPS**, не self-signed — иначе не работает `MediaRecorder`
  (голосовой ввод);
- `prisma generate` требует `DATABASE_URL` (из-за `prisma.config.ts` с `env()`)
  — на build-шаге Dockerfile подаётся фиктивный URL;
- `nest build` кладёт точку входа в `dist/src/main.js`, а не `dist/main.js` —
  поэтому entrypoint запускает `node dist/src/main`, а `start:prod` из
  `package.json` для прода неверен.
