# 🚀 Tracker: AI Budget App

**Описание проекта:** Приложение для ведения личного бюджета.
**Главная фича (Киллер-фича):** Ввод расходов голосом. Пользователь надиктовывает трату, AI распознаёт речь, парсит смысл и автоматически категоризирует покупку.
**Стек технологий:** React 19 (Vite), NestJS, PostgreSQL, Prisma ORM, Nexara (транскрибация) + OpenRouter (LLM-парсинг), Capacitor (мобильная версия, в планах), Local-first (в будущем).

> 📌 **Общий план-роадмап всего проекта.** Это единственный источник правды по
> этапам разработки — отмечай прогресс и бэка, и фронта здесь. README
> подпроектов хранят только свою специфику и не дублируют этапы.

## 🟠 Этап 3: "Киллер-фича" (Голосовой AI ввод)

**Цель:** Реализовать распознавание аудио и парсинг смысла через нейросети.

- [x] **Бэкенд: Работа с файлами**
  - [x] Настроить загрузку файлов в NestJS (использовать `Multer` для приема аудио).
  - [x] Создать эндпоинт `POST /transactions/voice` (принимает аудио ≤ 1 МБ, mime `audio/*`).
- [x] **Бэкенд: Интеграция распознавания и LLM**
  - [x] Зарегистрироваться и получить API Key (используем **Nexara** — российский Whisper-совместимый сервис; ключ в `.env` → `NEXARA_API_KEY`).
  - [x] Шаг 1: Интегрировать транскрибацию (аудио → текст). Реализовано через Nexara в `transactions.service.ts` (`transcribe`); endpoint возвращает `{ userId, text }`.
  - [x] Шаг 2: LLM-парсинг текста в JSON. Провайдер — **OpenRouter** (модель из `OPENROUTER_MODEL`, ключ `OPENROUTER_API_KEY` в `.env`; изначально был Google Gemini, переехали в июне 2026). Абстракция `TransactionParser` (модуль `src/llm/`) позволяет переключить провайдера одной строкой `useClass`.
    - [x] Контракт парсера: `TransactionParser.parse(text, categoryTitles)` → `ParsedTransaction`. На вход — текст траты + список **названий** категорий юзера, на выход — узкий объект.
    - [x] Системный prompt: LLM работает **как парсер**, а не «финансовый помощник». На выход — **только** JSON-объект.
    - [x] Набор полей `ParsedTransaction`: `amount`, `currency`, `description`, `type` (`INCOME`/`EXPENSE`), `category` (точное имя из списка юзера или `null`), `suggestedCategories`. Поля `id`, `userId`, `date` парсер **не возвращает** — это серверные поля (`id` от БД, `userId` из JWT, `date` = `now()`).
  - [x] Шаг 3: Сохранение распарсенного JSON в БД. Категория сопоставляется по имени → `categoryId` (case-insensitive). Совпадение есть → привязываем сразу. Совпадения нет → см. умную категоризацию ниже.
- [x] **Бэкенд: Умная категоризация (pending-флоу)**
  - [x] Если LLM не нашёл подходящей категории, трата **всё равно создаётся сразу** (сумма/тип уже известны и считаются в бюджете) с `categoryId = null`. Уточняется только категория.
  - [x] Схема: у `Transaction` добавлены `suggestedCategories String[]` (варианты от LLM; `[0]` — тот, что авто-применится) и `autoConfirmAt DateTime?` (дедлайн авто-подтверждения; `null` = категория уже решена). В API отдаётся вычисляемый флаг `categoryPending`.
  - [x] `POST /transactions/voice` возвращает **созданную транзакцию** + `suggestedCategories` + `categoryPending`.
  - [x] Эндпоинт `PATCH /transactions/:id/category` (тело `{ categoryName }`): находит-или-создаёт категорию юзера (`prisma.category.upsert`), привязывает, гасит `autoConfirmAt`. Покрывает и «согласиться с предложением», и «ввести свою».
  - [x] Фоновый крон (`@nestjs/schedule`, `@Cron(EVERY_MINUTE)` в отдельном `transactions.cron.ts`): если юзер молчит 5 минут, берёт `suggestedCategories[0]`, создаёт-или-привязывает категорию, гасит дедлайн.
- [x] **Фронтенд: Диктофон**
  - [x] Кнопка "Микрофон" на главном экране (`VoiceRecorderButton`).
  - [x] `MediaRecorder API` для записи голоса в браузере (подбор поддерживаемого mime: `audio/webm;codecs=opus`, fallback `audio/mp4` для Safari; авто-стоп через 60с как страховка от лимита 1 МБ).
  - [x] UI-анимация "Идет запись..." (вариант `destructive` + `animate-pulse`, при отправке — `Loader2` с надписью «Распознаём…»).
  - [x] Логика: тап — старт, тап — стоп → отправляем Blob (multipart, поле `audio`) через `useCreateTransactionFromVoice` → мутация инвалидирует кеш ленты.
- [x] **Фронтенд: Бейдж «Категория уточняется…» (pending-флоу)**
  - [x] Бейдж `CategoryPendingBadge` с обратным отсчётом до авто-подтверждения крона.
  - [x] По клику — чипсы с вариантами из `suggestedCategories` + поле «Своя категория».
  - [x] Сабмит — `PATCH /transactions/:id/category`, инвалидация `transactionKeys.all`.
- [x] **Дополнительно (сделано по ходу)**
  - [x] Страница деталей транзакции: подтверждение категории, редактирование, удаление.
  - [x] Страница просмотра категорий, ручное создание и удаление категории.
  - [x] Фиксированная нижняя панель для мобильной версии, переключение темы.
